при обновлении.

## 0.1.1 — Каркас и деплой · 27 августа 2026

Первый работающий релиз. Приложение собирается, открывается и показывает
версию сборки. Настоящих экранов ещё нет — они начинаются со следующего релиза.

### Что появилось

- **Демо по постоянной ссылке.** При каждом изменении интерфейса система сама
  собирается и выкладывается на GitHub Pages. Смотреть можно с телефона,
  показывать — кому угодно. Сервер для этого не нужен.
- **Дизайн-система в коде.** Палитра «Минимализм с деловой энергией» — графит,
  бирюза, оранжевый на выгоде — живёт в одном месте. Светлая и тёмная темы
  заданы вместе. Сменить брендинг теперь можно за час, а не за неделю.
- **Меню разделами-задачами:** «Найти услугу», «Мои заказы», «Документы
  и счета», «Компания». Горизонтальной строкой под поиском, как в утверждённых
  макетах.
- **Проверка вёрстки на узких экранах.** Страница не едет вбок ни при
  360 пикселях, ни при 1440.

### Что изменилось внутри

- 29 автоматических проверок, которые запускаются перед каждым изменением.
  Отдельно проверяется расчёт денег: комиссия и выплата всегда сходятся
  в копейку, потому что суммы считаются целыми числами в копейках.
- Встроена защита от главной архитектурной ошибки: части системы не могут
  залезать друг другу внутрь. Через год это позволит разделить систему
  на сервисы за десятки часов, а не переписать за сотни.
- Приложение падает на старте с понятной ошибкой, если не хватает настроек.
  Это специально: лучше не подняться на выкладке, чем подняться и отдавать
  ошибки из середины сделки.
- Первое изменение структуры базы данных: создана схема `platform`.
- Инструкции для сервера: запуск, обновление, ежедневные копии базы,
  проверка восстановления из копии.

### Что нужно сделать при обновлении

1. Скопировать `.env.example` в `.env` и заполнить
2. `pnpm install`
3. `pnpm db:migrate`
4. Для демо: включить в настройках репозитория Pages (Settings → Pages →
   Source → GitHub Actions)

### Известные ограничения

- **Резервное копирование написано, но ни разу не испытано** — нет сервера.
  Копия, из которой не восстанавливались, копией не является.
- Демо показывает только каркас: базы данных там нет, войти и оформить заказ
  нельзя.
- Шрифт пока системный: выбранный Manrope подключается вместе с первыми
  настоящими экранами.

## 0.0.1 — Фундамент · 27 августа 2026

Кода ещё нет. Заложено то, от чего зависит весь дальнейший код.

### Что появилось

- **Правила проекта** (`CLAUDE.md`): что строим, как устроена архитектура,
  какие соглашения по коду, как выглядит интерфейс, как со мной разговаривать.
- **Утверждённые макеты пути клиента**: каталог, карточка услуги, оформление
  заказа, сопровождение сделки. Плюс четыре состояния экрана и все токены.
- **План на три месяца вперёд** с задачами и часами.
- **Разборы решений**: требования к серверу, четыре схемы удержания денег,
  движок ставок комиссии, подписание документов.
- **Реестр решений** (`docs/06-open-questions.md`): что решено, кем, когда
  и почему — чтобы через полгода не обсуждать одно и то же заново.

### Ключевые решения этого этапа

| Решение | Следствие |
|---|---|
| Каталог — основной путь клиента, заявка — второй | витрина важнее подбора |
| Гарант работает удержанием денег до подписания акта | главное обещание продукта, проверяется тестом |
| Подрядчики регистрируются сами, карточки модерируются | каталог растёт без ручного труда |
| Работают все три схемы удержания денег | +32 часа, три юридические конструкции |
| Ставка комиссии — движок правил, а не число | категорийные, акционные, две лестницы скидок |
| Документы подписываются УКЭП, бумажный путь тоже остаётся | +100 часов, скидка за электронную подпись |
| Система делается для людей, а не для юрлиц | в шапке имя, а не ИНН |

### Что это сделало со сроком

Смета выросла с 298 до **548 базовых часов, около 658 с переделками** —
13–16 месяцев календаря против семи по исходному плану. Каждое расширение
названо ценой в момент решения; сокращения перечислены в
`docs/06-open-questions.md` и не берутся без вашего слова.
