# Стартовый пакет: как им пользоваться

Этот пакет уже разложен в корень репозитория — **до** того, как написана первая
строка кода. Claude Code читает `CLAUDE.md` автоматически в начале каждой сессии —
от качества этого файла напрямую зависит качество кода все семь месяцев.

Документ ниже описывает, зачем здесь каждый файл и как с ними работать дальше.

## Что здесь

| Файл | Для кого | Зачем |
|---|---|---|
| `CLAUDE.md` | агент, автоматически | Правила проекта: статус документа, архитектура, стек, границы модулей, соглашения, дизайн и интерфейс |
| `docs/01-architecture.md` | агент, по ссылке | Процессы, поток данных, внешние зависимости, правило деградации |
| `docs/02-modules.md` | агент, по ссылке | Ответственность модулей, форма контракта, события, статусы сделки |
| `docs/03-data-model.md` | агент, по ссылке | DDL первых трёх схем с пояснениями |
| `docs/04-glossary.md` | агент, по ссылке | Язык предметной области: одно понятие — одно слово |
| `docs/05-sprint-01.md` | агент и вы | Пять задач первого месяца с критериями приёмки |
| `docs/06-open-questions.md` | вы | Расхождения и решения, которые агент принимать не вправе |
| `prompts/kickoff.md` | вы | Готовые промпты: старт, очередная задача, ревью перед деплоем |
| `.env.example` | вы | Переменные окружения |
| `README.md` | люди | Что это за система и с чего начать |

## Порядок первого дня

| Шаг | Состояние |
|---|---|
| 1. Создать репозиторий, положить в него пакет | сделано — `1Lux0r1/Marketplace_for_business` |
| 2. Заменить рабочее имя `b2b-platform` на своё | сделано — везде `marketplace-for-business`, меняется одной заменой по репозиторию |
| 3. Взять VPS в России, домен, почтовый шлюз, S3-совместимое хранилище | за разработчиком |
| 4. Скопировать `.env.example` в `.env`, заполнить | за разработчиком, `.env` в `.gitignore` и в репозиторий не попадает |
| 5. Отправить агенту промпт из `prompts/kickoff.md` | сделано — ответ агента и план задачи 01-1 ждут подтверждения |
| 6. Не подтверждать план, пока не прочитаете его целиком | за разработчиком |

Первый час, потраченный на разбор плана, дешевле недели на разбор чужого кода.

Открытые вопросы и расхождения, найденные при разборе пакета, лежат
в `docs/06-open-questions.md` — их закрывает разработчик, а не агент.

## Как этим пользоваться дальше

**`CLAUDE.md` — живой документ, и он ваш.** Раздел 0 говорит агенту прямо: вы вправе
изменить или отменить любое правило, включая архитектурные, и менять вектор проекта.
Агент обязан один раз назвать цену решения и дальше выполнять, не блокируя и не повторяя
возражение. Пользуйтесь этим — правила существуют, чтобы не принимать одно и то же
решение дважды, а не чтобы связывать вам руки.

Каждый раз, когда агент делает не то и вы его поправляете, спросите себя:
это разовая ошибка или отсутствующее правило? Если второе — допишите правило.
К третьему месяцу этот файл станет главным активом проекта после самого кода.

**Не давайте задачу шире одного модуля.** Правки в двух модулях сразу — это два
плана, два ревью и два деплоя. Соблазн сэкономить время объединением приводит
к диффам, которые невозможно проверить.

**Перед каждым деплоем** прогоняйте промпт ревью из `prompts/kickoff.md`.
Пятнадцать пунктов, несколько минут — и они ловят ровно те ошибки, которые потом
всплывают при технической проверке перед раундом.

**Каждый месяц** сверяйтесь с планом: `docs/05-sprint-01.md` — только первый.
Спринты 02–07 расписаны в плане разработки; переносите их сюда по одному,
когда доходит очередь, а не все сразу.

## Оценка объёма

| Конфигурация | Часы | Срок при 62 ч/мес |
|---|---|---|
| Полная | 334 | 6,5–7,8 месяца |
| Урезанная (рекомендуется) | 298 | 5,8–7,0 месяца |

Разница — четыре сокращения: упрощённый кабинет подрядчика, лендинг на конструкторе,
готовая админ-панель, отказ от регулярных заказов до пилота. Все обратимы,
ни одно не трогает ядро: заявка, подбор, сделка, документы, оплата.

Коэффициент переделок 1,2 предполагает, что процесс партнёра выяснен в первые
два месяца. Без этого он ближе к 1,45 — и это разница примерно в месяц календаря.
