# Запуск на своей машине через Open Server Panel

**Если нужна простая версия без объяснений — щёлкните `deploy\ospanel\setup.bat`,
потом `deploy\ospanel\start.bat`. Больше ничего делать не нужно: настройка сама
найдёт базу и подставит её адрес.** Ниже — то же самое, но с объяснениями,
зачем что нужно.

**Написано под версию 6.5.1.** В пятой версии всё устроено иначе: там нет
встроенного проксирования, и красивый адрес пришлось бы настраивать вручную
через конфиг Nginx.

## Сначала главное: панель не запустит приложение сама

**Open Server Panel рассчитана на сайты на PHP.** Там всё устроено так: вы кладёте
файлы в папку — веб-сервер сам их читает и показывает. Наше приложение устроено
иначе. Это не набор файлов, а **программа, которая работает постоянно** и держит
свой номер входа (порт 3000). Веб-сервер её не запустит, не заменит и файлы
из папки показывать не станет — там нечего показывать.

Из этого не следует, что панель бесполезна. Она даёт два из трёх нужных кусков:

| Что нужно | Даёт ли панель 6.5.1 | Комментарий |
|---|---|---|
| **База данных** PostgreSQL | **Да** | Включается модулем, это половина работы |
| **Красивый адрес** `marketplace.local` | **Да** | Проксирование встроено, настраивается одним файлом |
| **Среда для приложения** Node.js 22+ | **Проще поставить отдельно** | В панели есть свой Node.js, но у него своя консоль и свои версии — лишний слой |

Дальше — по этим трём кускам. Порядок важен: без базы приложение не поднимется,
без Node.js его нечем запускать, а красивый адрес добавляется последним и вообще
не обязателен.

---

## Шаг 1. База данных

В панели откройте **Модули**, найдите **PostgreSQL** (нужна версия 16 или новее),
включите и запустите.

Записывать ничего не нужно: имя модуля и пароль настройка подберёт сама.
Достаточно, чтобы модуль был запущен.

**Почему именно PostgreSQL, а не MySQL, который в панели включён по умолчанию.**
Это не вкусовщина. Мы храним суммы, сроки и историю сделки, и от базы требуется
одно свойство: если операция не прошла целиком, она не проходит вовсе. Дальше на
это ляжут деньги, удерживаемые до подписания акта, — и переезд на другую базу
после этого будет стоить как половина проекта. Менять здесь нечего.

## Шаг 2. Node.js

Проверьте в командной строке:

```
node -v
```

Нужна версия **22 или новее**. Если команда не найдена или версия меньше —
поставьте Node.js с сайта `nodejs.org`, выбрав вариант **LTS**. Затем один раз:

```
npm install -g pnpm
```

`pnpm` — это то, чем ставятся библиотеки, из которых собрано приложение.

## Шаг 3. Первый запуск

Скачайте репозиторий (или откройте папку, если он уже скачан) и запустите:

```
deploy\ospanel\setup.bat
```

Скрипт сделает всё сам и расскажет по-русски, что делает: поставит библиотеки,
создаст файл настроек `.env`, придумает ключ подписи, заведёт две базы —
рабочую и для тестов — и создаст в них нужные таблицы.

**Адрес базы вписывать не нужно** — скрипт перебирает обычные варианты
и берёт первый работающий. Это сделано именно потому, что шестая версия панели
обращается к базе по имени модуля (`PostgreSQL-16`), а не по привычному
`localhost`, и помнить это наизусть человек не обязан.

Если база не нашлась вообще — скрипт скажет об этом прямо: значит, модуль
в панели не запущен. Включите его и запустите `setup.bat` снова, повторный
запуск безопасен.

Теперь:

```
deploy\ospanel\start.bat
```

Первый раз он будет собирать приложение — это минуту-две. Потом откроется
`http://localhost:3000`. **Окно закрывать нельзя:** закроете — приложение
остановится. Это нормально, так работают все программы такого рода.

## Шаг 4 (необязательный). Адрес marketplace.local

Чтобы открывать не `localhost:3000`, а `marketplace.local`. В шестой версии это
делается одним файлом настроек — своего конфига Nginx писать не нужно,
проксирование там встроено.

1. Создайте папку `C:\OSPanel\home\marketplace.local` — **имя папки станет
   именем домена.** Внутри неё создайте папку `.osp`.
2. Скопируйте туда готовый файл `deploy/ospanel/project.ini`. Должно получиться
   `C:\OSPanel\home\marketplace.local\.osp\project.ini`.
3. Перезапустите панель (или обновите список доменов в её меню).

Внутри файла всего три строки смысла: передавать все запросы на `127.0.0.1:3000`,
где работает наше приложение. Ничего больше настраивать не нужно.

**После этого обязательно поправьте одну строку в `.env`:**

```
APP_URL=http://marketplace.local
```

Это не косметика. По этому адресу приложение решает, помечать ли ключ входа
как «только для защищённого соединения». Ошибётесь — вход перестанет работать,
причём молча: форма отправится, ошибки не будет, а внутрь вас не пустит.
После правки приложение нужно перезапустить.

## Что на своей машине работать не будет — и это правильно

**Письма никуда не уходят.** Они печатаются в том окне, где запущено приложение.
Код подтверждения при регистрации ищите там же — в строке со словом `body`.
Настоящая отправка требует почтового сервера в России (§8 `CLAUDE.md`),
и включать её на домашней машине незачем.

**Проверка компании по ИНН не работает.** Справочник не подключён — это открытый
вопрос Q20 в `docs/06-open-questions.md`. Реквизиты вводятся руками.

**Вход по телефону не работает.** Некому отправить код подтверждения — тот же Q20.
Вход по почте и паролю работает полностью.

**Фоновый процесс не запускается.** Он появится в задаче 01-3. Сейчас он умеет
только запускаться и останавливаться, поэтому `start.bat` его не трогает.

## Что делать дальше

Всё в папке `deploy\ospanel`, запускается двойным щелчком:

| Задача | Файл |
|---|---|
| Запустить сайт | `start.bat` |
| Остановить | закрыть окно, где он запущен |
| Обновиться до свежей версии | `update.bat` |
| Посмотреть, что в базе | `db-show.bat` |
| Стереть все данные и начать заново | `db-reset.bat` |

**Отдельного «стоп-файла» намеренно нет.** Такой файл обычно останавливает все
программы Node на машине разом — вместе с чужими, к нашему проекту отношения
не имеющими. Закрыть своё окно надёжнее.

## База данных

**Смотреть, что внутри, — `db-show.bat`.** Он отвечает на вопрос, который
возникает чаще всех: сколько зарегистрировалось компаний и людей, кто последний,
подтвердил ли почту, уходили ли письма. Отдельная программа для этого не нужна.

**Начать заново — `db-reset.bat`.** Стирает данные, оставляя структуру:
регистрироваться можно сразу же. Спрашивает подтверждение словом, потому что
отменить это нельзя. На боевом сервере отказывается работать.

**Смотреть таблицы напрямую** — если понадобится, ставится pgAdmin 4
с сайта `pgadmin.org`, бесплатно. Адрес, логин и пароль базы лежат в файле
`.env` в строке `DATABASE_URL`. Оговорка: это инструмент разработчика, он
показывает таблицы как есть. Человеческий разбор данных — это интерфейс
администратора, он запланирован на третий спринт (`docs/05-sprint-03.md`).

**Демо-данных пока нет.** `pnpm db:seed` существует, но наполнять ещё нечем:
категории и подрядчики появятся в задаче 01-4.

## Логи

Логи — это то, что программа пишет о своей работе: что произошло, когда
и с чем. Они идут прямо в то окно, где запущен `start.bat`.

**На своей машине они выводятся по-человечески** — время, важность, что
случилось, и текст письма отдельным блоком. Именно там ищется код
подтверждения при регистрации.

На боевом сервере тот же лог пишется в файл в виде JSON — это формат,
который читают программы сбора логов, а не человек. Переключение — переменная
`LOG_FILE` в `.env`: пусто значит «на экран по-человечески», путь к файлу
значит «в файл для программ».

Что искать в окне, когда что-то не так:

- `ошибка` и `сбой` — красным, это то, что сломалось
- `внимание` — жёлтым, работает, но не так, как задумано
- `инфо` — обычный ход дела

Персональные данные в логи не пишутся намеренно (§8): телефоны, адреса
и почты в них не попадают. Исключение — режим `MAIL_TRANSPORT=log`, где
письмо печатается целиком: он для своей машины, на сервере включать его нельзя.

## Обновления

`update.bat` забирает свежую версию, обновляет библиотеки, накатывает
изменения структуры базы и говорит, что готово. Данные при этом остаются.

**Работает только если папка получена через Git.** Если вы скачали архив
кнопкой «Download ZIP», обновиться на месте нельзя — Git и есть то, что
умеет догружать изменения. Тогда либо скачивать архив заново каждый раз,
либо один раз поставить Git с `git-scm.com` и перейти на `update.bat`.

Второе лучше: скачивание архива каждый раз — это удалить папку, скачать,
распаковать, настроить заново. Обновление через Git — один щелчок, и
настройки не теряются.

## Чем это отличается от боевого сервера

Своя машина — чтобы смотреть и показывать, а не чтобы на ней работали заказчики.
Настоящий сервер описан отдельно: требования в `docs/08-server-requirements.md`,
установка и обновление в `deploy/README.md`. Три отличия, которые важно понимать:

- **На своей машине нет резервных копий.** На сервере они каждую ночь и проверяются
  восстановлением. Всё, что вы наберёте локально, живёт до первой поломки диска.
- **Приложение не поднимается само.** На сервере за этим следит система: упало —
  перезапустилось. Здесь закрыли окно — значит, остановилось.
- **Персональные данные.** Пока это ваши собственные пробные записи — вопросов нет.
  Как только появятся настоящие люди, машина должна стоять в России и быть
  сервером, а не рабочим компьютером (§8 `CLAUDE.md`).
