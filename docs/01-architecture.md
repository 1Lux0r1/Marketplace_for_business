# Архитектура — справка для агента

Сжатая версия. Полное обоснование решений — в отдельном документе «Монолит, готовый распасться».

## Процессы

Три процесса, все на одном VPS в России, под systemd:

| Процесс | Что делает | Падение означает |
|---|---|---|
| `app` | Next.js: интерфейс, серверные экшены, вебхуки, Telegram-бот | Система недоступна |
| `worker` | Разбор `platform.outbox`: уведомления, метрики, фоновые вызовы ИИ | События копятся, обработаются позже |
| `ai-service` | Python + FastAPI: разбор заявки, скоринг, риск, подсказка цены | Подбор идёт по правилам, сделки не встают |

## Поток данных

```
[Кабинет клиента]  [Кабинет подрядчика]  [Telegram-бот]  [Админка]
        └──────────────────┴──────────┬───────┴──────────────┘
                                      │ HTTP
                             ┌────────▼─────────┐
                             │   app (Next.js)  │──── POST /parse /score ───▶ ai-service
                             │  модули 1..9     │◀ ─ ─ таймаут 2 с → правила ─ ┘
                             └───┬──────────┬───┘
              своя схема         │          │  событие в той же транзакции
                     ┌───────────▼──┐   ┌───▼──────────────┐
                     │ схемы модулей│   │ platform.outbox  │
                     └──────────────┘   └───┬──────────────┘
                                            │ опрос каждые 5 с
                                      ┌─────▼──────┐
                                      │   worker   │──▶ Telegram, SMTP, метрики
                                      └────────────┘
```

Ключевой механизм — **outbox**. Он даёт надёжность очереди без установки очереди:
если воркер упал, события накопятся; если упала транзакция — события просто не будет.
Побочно `platform.outbox` становится полным журналом системы, из которого потом
считаются time-to-match, доля повторных заказов и когорты.

## Внешние зависимости

| Что | Зачем | Если недоступно |
|---|---|---|
| Эквайринг | Ссылки на оплату, вебхуки о платеже | Оплата по счёту вручную, статус ставит оператор |
| S3-совместимое хранилище в РФ | PDF договоров, счетов, актов | Локальный диск как запасной вариант |
| SMTP | Письма клиентам и подрядчикам | Копятся в outbox |
| Telegram Bot API | Приём заявок, уведомления подрядчикам | Копятся в outbox |
| ai-service | Разбор, скоринг, риск | Правила — см. `docs/02-modules.md` |

## Правило деградации

Каждый внешний вызов имеет таймаут и запасной путь. Ни один внешний сервис
не должен уметь остановить сделку. Формулировка для проверки любого нового вызова:
**«если это не ответит — что увидит клиент?»** Ответ «ошибку» означает, что запасной
путь не написан.
